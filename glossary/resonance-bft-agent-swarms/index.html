Resonance BFT (rBFT)
Three witnesses who don't know each other.

You ask five people the same question independently. Three say the same thing. Two say something different. You go with the three. Not because democracy is truth. Because independent agreement is harder to fake than solo conviction. That's Resonance BFT.

Resonance BFT
rBFT  /ˈrez.ə.nəns biː.ɛf.tiː/  ·  noun
The application of Byzantine Fault Tolerance principles to AI agent swarms. a consensus mechanism that enables autonomous agents to reach agreement on shared state even when individual agents produce conflicting, hallucinated, or faulty outputs. Resonance BFT adapts the fault-tolerance model from distributed systems (where nodes may crash or act maliciously) to multi-agent AI systems (where agents may hallucinate, misinterpret, or produce inconsistent results). The mechanism requires a supermajority of independent agents to converge on the same output before the output is accepted as valid.
Distinguished from traditional Byzantine Fault Tolerance, which assumes adversarial nodes that may act maliciously. Resonance BFT assumes probabilistic faults. Agents are not malicious, but they are fallible. The fault model changes from 'this node is trying to deceive' to 'this agent may have hallucinated.' The consensus mechanism is similar. The trust model is different.
The Problem

LLMs hallucinate. Agent swarms without consensus amplify that.

A single LLM producing a hallucinated answer is a known risk. Multiple LLMs producing independent answers for the same query. and disagreeing. is a systems problem. Without a consensus mechanism, the orchestrating system has no principled way to determine which output is correct.

This is the problem Resonance BFT solves. It borrows from Byzantine Fault Tolerance, a concept from distributed systems research dating to the Lamport-Shostak-Pease paper (1982). In distributed systems, BFT ensures that a network of nodes can reach consensus even when some nodes fail or act maliciously. The same principle applies to agent swarms. with one critical difference in the fault model.

A single LLM hallucinating is a known risk. Multiple LLMs hallucinating independently on the same query is a systems problem. Without consensus, the orchestrator has no principled way to choose. Resonance BFT provides the principle.

The Distinction

Traditional BFT vs. Resonance BFT. same math, different trust model

The consensus threshold is identical. The fault model is fundamentally different. Understanding this distinction is what makes Resonance BFT a new concept, not a rebrand of existing BFT.

Traditional BFT
Fault model: adversarial (nodes may act maliciously)
Faulty nodes: identified and excluded from consensus
System: distributed database or blockchain network
Trust assumption: nodes are either correct or Byzantine
Recovery: faulty nodes removed or restarted
Threshold: tolerates f faults in 3f + 1 nodes

Same math
Resonance BFT
Fault model: probabilistic (agents may hallucinate)
Faulty outputs: identified and discarded; agent stays in swarm
System: multi-agent AI swarm (LLM-based agents)
Trust assumption: agents are correct on most queries, fallible on some
Recovery: agent may produce correct output on next query
Threshold: tolerates f faults in 3f + 1 agents (same)

The key insight: in traditional BFT, a faulty node is a permanent condition that requires removal. In Resonance BFT, a faulty output is a transient condition. the same agent may produce a correct answer on the next query. This is why agents are not excluded from the swarm when they produce a divergent output. They are flagged for review, and their output is discarded for that query, but they remain part of the consensus pool.

The Mechanism

How Resonance BFT works in practice

The consensus process has four steps. Each step mirrors traditional BFT but adapts to the probabilistic fault model of LLM-based agents.

01
Independent Execution
Each agent in the swarm processes the query independently. No agent sees another agent's output before producing its own. This independence is critical. if agents can see each other's outputs, they may converge through imitation rather than independent reasoning, producing false consensus.
02
Output Collection
All agent outputs are collected and compared. The comparison is semantic, not exact. outputs that convey the same information with different wording are treated as equivalent. This requires a comparison layer (typically an embedding-based similarity check or a designated judge agent).
03
Convergence Check
If a supermajority of agents (≥ 2f + 1 of 3f + 1) produce semantically equivalent outputs, the output is accepted as valid. Divergent outputs are flagged. If no supermajority converges, the query is retried with modified parameters or escalated to human review.
04
Fault Logging
Divergent outputs are logged with agent ID, query, and output. Agents that consistently diverge are flagged for review. not removed. An agent that diverges on 30% of queries may need prompt revision or parameter adjustment. An agent that diverges on 5% may just have a higher base hallucination rate.

Four steps. The independence in step one is critical. If agents see each other's outputs before producing their own, they converge through imitation. False consensus. The independence is what makes the consensus trustworthy.

Application

Resonance BFT in the AURE Constellation

The AURE Constellation is the multi-agent ecosystem where Resonance BFT operates. The ARM, Signal, and Arctura agents each process queries independently. research, data verification, and strategic analysis respectively.

Without Resonance BFT, the AURE Constellation is a collection of independent agents whose outputs may conflict. With it, the swarm is a fault-tolerant system: when the agents agree, confidence is high. When they disagree, the consensus mechanism determines which output to trust and which to flag.

The connection to Entity Authority is direct. An entity cited by a single agent is a claim. An entity cited by a supermajority of independent agents. each using different retrieval paths and reasoning chains. is a verified claim. Resonance BFT is the mechanism that converts independent agent agreement into verified Share of Model measurement.

The Math

The 3f + 1 threshold

Resonance BFT follows the standard BFT threshold established by Practical Byzantine Fault Tolerance (PBFT): the system tolerates up to f faulty agents in a swarm of 3f + 1 agents.

Threshold Table
Swarm of 4 agents → tolerates 1 faulty output (75% agreement required)
Swarm of 7 agents → tolerates 2 faulty outputs (71% agreement required)
Swarm of 10 agents → tolerates 3 faulty outputs (70% agreement required)
Swarm of 13 agents → tolerates 4 faulty outputs (69% agreement required)

As the swarm grows, the agreement threshold decreases slightly (from 75% to 69%), but the absolute number of tolerable faults increases. This is the scaling advantage of BFT. larger swarms are more fault-tolerant, not less.

The trade-off is latency. More agents means more independent execution time and more comparison overhead. The AURE Constellation uses 4 agents (tolerating 1 fault) for speed-critical queries and 7 agents (tolerating 2 faults) for high-stakes decisions.

FAQ

Common questions about Resonance BFT

What is Resonance BFT?
Resonance BFT is the application of Byzantine Fault Tolerance principles to AI agent swarms. It is a consensus mechanism that enables autonomous agents to reach agreement on shared state even when individual agents produce conflicting, hallucinated, or faulty outputs. The mechanism requires a supermajority of independent agents to converge on the same output before it is accepted as valid.
How is Resonance BFT different from traditional BFT?
Traditional BFT assumes nodes may crash or act maliciously. the fault model is adversarial. Resonance BFT assumes agents may hallucinate, misinterpret context, or produce inconsistent outputs. the fault model is probabilistic. In traditional BFT, faulty nodes are identified and excluded. In Resonance BFT, faulty outputs are identified and discarded, but the agent remains in the swarm (it may produce correct outputs on the next query).
Why do AI agent swarms need Byzantine Fault Tolerance?
LLMs hallucinate. When multiple agents operate independently, they may produce conflicting outputs for the same query. Without a consensus mechanism, the system has no way to determine which output is correct. Resonance BFT provides that mechanism: if 3 of 5 agents produce the same answer and 2 produce different answers, the 3-agent majority is accepted and the 2 divergent outputs are flagged for review.
What is the fault tolerance threshold for Resonance BFT?
Resonance BFT follows the standard BFT threshold: the system tolerates up to f faulty agents in a swarm of 3f + 1 agents. A swarm of 4 agents tolerates 1 faulty output. A swarm of 7 agents tolerates 2. The threshold is the same as traditional BFT. the difference is the nature of the fault (hallucination vs. adversarial behavior).
How does Resonance BFT relate to the AURE Constellation?
